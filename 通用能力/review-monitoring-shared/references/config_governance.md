# 配置治理与运营维护手册

## 结论

SOP-first 新增表不废弃旧表。新增 SOP 表承担“配置控制面”，旧事件、触达、数据源、指标和部分 legacy 表继续承担运行态、基础域资产或兼容职责。

当前原 Base 已新增 `配置治理目录表`，作为运营和工程共同查看的表级治理入口：

| 表名 | 系统表ID | 作用 |
|---|---|---|
| 配置治理目录表 | `tbl0JIoqJWVWlIHH` | 标记每张表的表类型标签、当前定位、谁来维护、是否影响 SOP 运行配置、是否由系统自动写入和保留/迁移策略 |

该表不参与 `sop_config.v1` 编译，不参与运行态写回，只用于治理和运营可见性。

`系统表ID（无需填写）` 是工程排障和脚本联动字段，运营同学日常不用理解或维护。

## 表类型标签

| 标签 | 含义 | 处理原则 |
|---|---|---|
| 权威配置 | 当前 SOP-first 配置权威源 | 配置变更后必须导出、lint、shadow，触达前必须 canary |
| 基础域资产 | 跨 SOP 复用的数据源、指标、模板或治理目录 | 不因单个 SOP 临时改口径，需审批 |
| 运行产物 | 事件、触达、案例等线上运行记录 | 运营只读审计，禁止手工改状态 |
| 兼容旧表 | 迁移期保留的旧配置入口 | 不新增能力，逐步被 SOP-first 表替代 |
| 工程契约 | process、模板、节点等代码契约 | 工程维护，运营只读 |
| 运营日常维护 | 运营可在常规流程中维护 | 仍需 lint/shadow/canary 后发布 |
| 运营审批维护 | 运营可提出变更，但需工程/数据 owner 审批 | 变更前确认口径、字段和影响面 |
| 只读审计 | 用于排查和复盘 | 不作为配置入口 |

## 维护分层

### 运营日常维护

| 表 | 运营可改内容 | 发布要求 |
|---|---|---|
| SOP 注册表 | SOP 启停、运行频率、运行模式、默认报告类型、默认触达策略 | 导出配置 -> lint -> shadow |
| SOP 规则组表 | 规则启停、等级引用、窗口策略、路由粒度 | 导出配置 -> lint -> shadow；阈值变更需复核 |
| SOP 等级字典表 | SLA、是否需要人工确认、默认受众策略 | P0/P1 变更需人工审批 |
| Owner Source 注册表 | owner 映射、兜底策略、负责人信息 | 扩面前必须替换默认 owner |
| 报告发布策略表 | 报告目标、auto_send、canary 单目标、幂等策略 | auto_send 需要授权文件 |

### 运营审批维护

| 表 | 为什么需要审批 |
|---|---|
| SOP 指标观测对象表 | 影响取数口径和 canonical metric |
| SOP 路由策略表 | 改错会发错人或漏路由 |
| Report Template 注册表 | 模板文件仍在代码仓库，需同步工程变更 |
| 数据源表 | 跨 SOP 数据源资产，不因单个 SOP 临时改口径 |
| 指标注册表 | 全局指标口径源，影响多个 SOP |
| 触达模板表 | 影响触达文案和人工确认口径 |
| 等级字典表 | 旧链路仍可能引用，需兼容 SOP 等级字典 |
| 撞线规则表 | legacy 规则入口，不再承接新 SOP 能力 |
| 责任路由表 | legacy 路由入口，逐步迁移到 Owner Source |
| 配置治理目录表 | 新增表或治理分类变化必须同步登记 |

### 工程维护只读

| 表 | 原因 |
|---|---|
| SOP 节点表 | 编排 DAG/状态机骨架，改错会破坏执行顺序 |
| Process Skill 注册表 | 输入输出契约、依赖和校验命令属于工程契约 |

### 运行态只读审计

| 表 | 处理原则 |
|---|---|
| 事件表 | 由线上运行链路写入状态和触达关联，运营只读排查 |
| 触达记录表 | 由触达链路写入 message_id、card_hash、idempotency_key 等审计字段 |
| 案例沉淀表 | 后续由关闭/复盘流程写入，MVP 暂不作为配置入口 |

## 旧表废弃策略

当前不删除旧表。先按治理目录标记，再观察一段线上运行周期。

| 旧表 | 当前状态 | 迁移策略 |
|---|---|---|
| 撞线规则表 | 兼容旧表 | 新 SOP 编排以 `SOP 规则组表` 为准；旧表不新增能力 |
| 责任路由表 | 兼容旧表 | 新 SOP 编排以 `Owner Source 注册表` + `SOP 路由策略表` 为准 |
| 等级字典表 | 基础域权威 + 兼容旧表 | SOP-first 优先使用 `SOP 等级字典表`，旧链路继续保留 |
| 本地 JSON 样例 | 回滚快照/测试样例 | 不作为线上配置入口，保留用于测试和回滚 |

## 配置发布流程

1. 运营在对应维护视图中修改配置。
2. 导出 Base 配置为本地 JSON。
3. 运行 `config_linter.py`，要求 `summary.status=passed`。
4. 用编译后的 `sop_config.v1` 跑 shadow，对比现有输出。
5. 单目标 canary 验证报告、触达和写回。
6. 明确授权后再扩大等级、owner 或 SOP 范围。

## 新增表规则

任何新 Base 表创建后，必须同步登记到 `配置治理目录表`，至少填写：

- `配置表名称`
- `系统表ID（无需填写）`
- `表类型标签`
- `当前定位`
- `谁来维护`
- `运营可直接修改`
- `会影响SOP运行配置`
- `系统会自动写入`
- `怎么维护`
- `保留/迁移策略`

未登记的表默认视为“工程维护/暂不运营维护”，不得作为运营入口。
