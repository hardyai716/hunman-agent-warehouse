# data_readiness — 数据就绪校验（前置 gate）

> 分析前的**强制前置门禁**。只有「已就绪」才允许进入取数与分级判断；「未到位/异常/未校验」一律停止，不给分级结论——**宁可不出结论，绝不误报**。

## 为什么必须先校验

数据没到位就跑，会因「某天分区缺失导致日均虚低、打标率虚低」而误判出假的低效策略。所以取数前必须确认目标分区真实到位。

## 校验步骤

1. **算目标分区**：`run_date - data_lag_days = D-N`（最新可取分区）。
   - 单周期/双周期规则涉及最早分区 `D-N-13`（前7天起点）。
   - P0 四周规则涉及最早分区 `D-N-27`（w4 起点）。
   - 取所有待跑规则涉及的**最早分区**作为校验下界。
2. **探测分区存在且有数据**：对目标分区跑一条计数探测 SQL（`LIMIT 1` 或 `COUNT`），确认返回行数 > 0。
3. **判定就绪状态**：

| 探测结果 | 就绪状态 | 动作 |
|---|---|---|
| 目标分区存在且有数据 | 已就绪 | 进入取数（步骤 3-4） |
| 目标分区不存在 / 数据量为 0 | 未到位 | **本轮停止，报告「未就绪」**，不给分级结论 |
| 查询报错 / 权限不足 / 数据源不可访问 | 异常 | **本轮停止**，权限类透出申请链接转人工 |
| 本轮未真正访问数据源 | 未校验 | 不得伪造「已就绪」，不得编造结论 |

## 探测 SQL 示例

```sql
SELECT COUNT(*) AS cnt
FROM olap_content_security_community.dws_sft_tcs_review_task_detail_di
WHERE `[p_date]` = 'D-N'
LIMIT 1
```

> 探测用当前 runtime 的风神查数工具执行（入口 A/B 均可，见 [data_fetch.md](data_fetch.md)）；分区字段引用按入口选 `` `[p_date]` `` 或 `` `日期` ``。

## 硬规则

- **数据延迟天数以结构化字段/入参 `data_lag_days` 为准**，不读自然语言「数据延迟说明」。
- 目标分区未到位时**不触发**、不降级硬跑，避免误报。
- 本 Skill 只读、不回写就绪状态到任何配置表；就绪结论只在本轮内存内使用并报告给用户。
- 只有「已就绪」进入分级判断；其余状态一律停止并如实报告原因。
