# analysis_output — 分级清单格式化与报告结构

> 本文定义「命中行 → 分析报告」的输出规范。目标：让使用者一眼看清**哪些策略低效、有多严重、证据是什么**。

## 格式化规则（对命中行做展示层转换）

| 字段（模板别名） | 格式要求 | 示例 |
|---|---|---|
| `reason` | 原始文本 | `reason_1001` |
| `avg_jinshen`（日均进审量） | 整数 + 千分位 | `58000` → `58,000` |
| `avg_wanshen`（日均完审量） | 整数 + 千分位 | `42000` → `42,000` |
| `avg_dabiao`（日均打标量） | 整数 + 千分位 | `210` → `210` |
| `ratio_val`（打标率） | 百分比保留 2 位小数（×100） | `0.0235` → `2.35%` |
| `hit_condition`（命中条件） | 原样文本，多条件用「；」分隔 | `单周高量低效（近7天日均进审>5000且打标率<3%）` |
| `等级` | P0/P1/P2/notice | `P1` |

**排序**：默认按 `avg_wanshen`（日均完审量）**降序**——占用人审产能最多的低效策略排最前，优先处理。

## evidence 要求（每条结论必须带真实数值）

不允许只给「reason_1001 低效」这种光秃结论。每条低效策略必须附带命中行的真实数值作为 evidence：

```
reason_1001【P1】
  日均进审量：58,000  日均完审量：42,000  打标率：0.21%
  命中条件：单周高量低效（近7天日均进审>5000且打标率<3%）
  evidence：日均进审 58,000 > 5,000；打标率 0.21% < 3%
```

进审量过低（低于该规则的进审量守卫）的策略不会进入命中结果，无需额外标注。

## 报告结构（三段式）

### 1. 分级汇总

```
## 近7天低效策略分析（2026-06-25 ~ 2026-07-01）

| 等级 | 命中数 | 说明 |
|---|---|---|
| P0 | 0 | 无 |
| P1 | 2 | 高量持续低效 |
| P2 | 5 | 单策略低效 / 低效环比增长 |
| notice | 12 | 打标率偏低（观察级） |
```

### 2. 五个 sheet（🔴 强制：一个文件 5 个 sheet）

**一个表格文件（工作簿）内放 5 个 sheet：`notice` / `P2` / `P1` / `P0` / `综合`。**
- 四个**等级 sheet**（notice/P2/P1/P0）= 各等级 SQL 的完整命中，**互不跨级去重**——同一 reason 命中多级就在多个等级 sheet 各自出现（如 `N1_chuxing` 同时进 P0/P1/P2/notice）。
- 第 5 个**综合 sheet** = 四级**跨级去重取最高等级**（P0>P1>P2>notice），每个 reason 一行，多一列「等级」。
- 各 sheet 内按日均完审量降序。禁止拆成多个文件，也禁止只给一张扁平表。

```
【sheet: P0】（该等级完整命中）
| reason | 日均进审 | 日均完审 | 日均打标 | 打标率 | 命中条件 |
|---|---|---|---|---|---|
| reason_1001 | 58,000 | 42,000 | 88 | 0.21% | 持续四周低效（严重） |

【sheet: P1 / P2 / notice】同上结构，各装本等级完整命中（不去重）

【sheet: 综合】跨级去重取最高等级，多一列「等级」
| 等级 | reason | 日均进审 | 日均完审 | 日均打标 | 打标率 | 命中条件 |
|---|---|---|---|---|---|---|
| P0 | reason_1001 | 58,000 | 42,000 | 88 | 0.21% | 持续四周低效（严重） |
```

> 落地文件（飞书表格 / xlsx）= **1 个工作簿 5 个 sheet**；若工具只能单表 CSV，则导 5 个 CSV 但对应同一次分析、命名 `<前缀>_notice/_P2/_P1/_P0/_综合.csv`，并说明同属一份结果。

### 3. 数据说明（口径透明，便于核对）

```
### 数据说明
- 分析周期：近7天（本期 2026-06-25~2026-07-01，上期 2026-06-18~2026-06-24）
- 数据分区：p_date，数据延迟 T+1，最新分区 2026-07-01
- 打标率口径：打标量 / 完审量（分母完审量），基于内层 SUM 重算
- 日均口径：SUM(指标) / COUNT(DISTINCT p_date) 动态天数
- 样本池：默认 base_filter（社区人工审核场景白名单 + 标题黑名单 + 机审标签白名单）
- 取数底座：风神数据集（bytedcli + bytedance-aeolus），物理表 olap_content_security_community.dws_sft_tcs_review_task_detail_di
```

## 输出硬规则

- **默认全等级**：用户未点名等级时，notice/P2/P1/P0 四级都跑；仅用户显式限定时才出子集。
- **一个文件五个 sheet**：四个等级 sheet + 一个综合 sheet 放同一工作簿，绝不拆成多个文件、也不压成一张扁平表。
- **等级 sheet 不去重、综合 sheet 去重**：等级 sheet 各装该等级完整命中（同一 reason 可跨级重复出现）；综合 sheet 跨级取最高等级、每个 reason 一行。
- **不臆造**：某级无命中则该 sheet 为空并注明「本期 0 条」，取数失败就写失败原因，不编数值凑清单。
- **产出即终点**：报告到此为止，本 Skill 只交付分级清单与证据。
- **数据说明必带**：每份报告都要带口径说明段，让使用者能复核打标率分母、日均天数、周期窗口是否正确。
